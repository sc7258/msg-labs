# msg-keeper 클릭형 와이어프레임

`index.html`을 브라우저에서 열면 됩니다. 별도의 설치나 빌드가 필요하지 않습니다.

이 시안은 Android 앱의 모바일 UI를 검토하기 위한 것입니다. 받은함, 차단함, 검색, 규칙, 설정을 한 가지 디자인으로 구성했습니다. 브라우저 주소 뒤에 `?preview=inbox`, `?preview=quarantine`, `?preview=search`, `?preview=rules`, `?preview=settings`를 붙이면 해당 화면부터 바로 볼 수 있습니다.

## 확인 흐름

1. **데모 화면 시작하기**를 눌러 일반 목록을 봅니다.
2. 메시지를 눌러 상세와 차단함 이동을 확인합니다.
3. **차단함**에서 사유를 확인하고 일반 목록으로 복원합니다.
4. **규칙**에서 발신자 또는 내용 규칙을 추가합니다.
5. 오른쪽 위 **＋**로 테스트 SMS를 만들고 자동 분류 결과를 확인합니다.
6. **검색**에서 발신자와 본문을 찾고 일반 목록·차단함 필터를 바꿉니다.
7. **설정**에서 데모 수집을 끄고 테스트 SMS 수신이 멈추는 상태를 확인합니다.

데모 상태는 브라우저 로컬 저장소에 보관합니다. **설정 → 데모 데이터 처음으로**를 누르면 초기 화면으로 돌아갑니다. 빈 목록은 일반 목록의 메시지를 모두 차단함으로 옮겨 확인할 수 있습니다.

이 파일은 기획 검토용 화면입니다. 실제 SMS 권한, 수집, 발송, 차단, 원본 문자함 수정, 계정 로그인, 서버 API는 연결하지 않았습니다. 첫 개발 범위는 Android Kotlin 앱에서 기기 내 SMS 수집·분류·차단함·복원·검색이며, 카카오톡 알림과 Gmail은 후속 단계입니다. 첫 Android 앱은 차단함으로 이동한 항목을 90일 뒤 앱 안에서 자동 삭제합니다. 기존 문자 앱의 원본은 유지합니다. 이 화면 데모는 자동 삭제를 시뮬레이션하지 않습니다.
